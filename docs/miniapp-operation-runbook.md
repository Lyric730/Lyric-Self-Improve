# 云瀚台球小程序上线使用路径

状态：v1.0
日期：2026-06-10

## 1. 当前结论

这份手册只回答一个问题：门店第一次拿到小程序后，应该按什么顺序使用。

当前小程序不是“打开就能营业”的状态，必须先完成云端初始化和权限绑定。正确顺序是：

1. 云开发准备完成。
2. 初始化首个老板账号。
3. 老板配置门店规则。
4. 老板给员工授权。
5. 员工设置球桌到点时间。
6. 球友扫码发起挑战。
7. 双方完成比赛并由云函数结算。
8. 大屏读取真实榜单。

## 3. 初始化首个老板账号

负责人：老板本人

页面：

```text
/pages/setup-owner/setup-owner
```

操作：

1. 老板本人用微信打开小程序。
2. 进入门店初始化页面。
3. 确认页面显示当前 OpenID。
4. 输入云函数环境变量里的 `BOOTSTRAP_OWNER_SECRET`。
5. 点击初始化老板账号。

成功后云数据库应出现：

- `store_members` 中有一条记录：
  - `storeId = default`
  - `openid = 当前老板微信 OpenID`
  - `role = owner`
  - `status = active`

注意：

- 一个门店只能初始化一个首个老板。
- 这个入口不是给顾客看的，也不是日常操作入口。
- 初始化完成后，可以删除或更换 `BOOTSTRAP_OWNER_SECRET`。

## 4. 老板配置门店规则

负责人：老板

页面：

```text
我的 -> 老板端
```

老板必须先配置：

| 配置 | 作用 |
| --- | --- |
| 玩法模板 | 决定抢 5、抢 7、抢 10 是否开放 |
| 底分 | 顾客开局时可选的风险底分 |
| 倍率 | 顾客开局时可选的积分倍率 |
| 普通随机奖励 | 普通局结算时的系统随机奖励 |
| 冲刺奖励 | 接近续时时激励继续打的奖励 |
| 新用户积分 | 新会员第一次建档的初始积分 |
| 开台赠分 | 员工绑定开台会员后发放 |
| 兑换门槛 | 前台积分兑换最低门槛 |
| 店内定位 | 有效挑战必须在门店范围内 |
| 门店经纬度 | 100 米防刷分计算依据 |
| 大屏榜单 | 电视榜单标题和刷新文案 |

成功后云数据库应出现：

- `admin_configs` 中有一条门店配置记录。

上线红线：

- 如果门店经纬度没填，定位 gate 会返回 `skipped`，不会真正防止店外刷分。
- 上线前必须用真机在店内、店外分别测试一次。

## 5. 老板给员工授权

负责人：老板

页面：

```text
我的 -> 老板端 -> 人员权限
```

操作：

1. 员工先打开自己的小程序。
2. 员工进入 `我的 -> 会员码`。
3. 老板在老板端点击“扫码选择”。
4. 扫员工会员码。
5. 选择目标身份：
   - `员工`：可进入前台工作台和小程序大屏。
   - `大屏`：只用于电视榜单访问。
   - `普通球友`：撤销员工或大屏权限。
6. 点击保存人员权限。

成功后云数据库变化：

- `store_members.role` 更新为 `staff` / `screen` / `player`。
- `operation_logs` 写入老板授权记录。

注意：

- 不能在这里修改老板账号。
- 不能把当前老板自己降权。

## 6. 员工开台

负责人：前台员工

页面：

```text
我的 -> 员工端
```

第一版“开台”的定义：

- 不是替代原开台软件收银。
- 只是在小程序里记录某个球桌的到点时间。
- 这个到点时间用于判断顾客能不能发起有效挑战。

操作：

1. 选择球桌，例如 `T01`。
2. 选择到点时间，例如 `22:30`。
3. 可选：扫码绑定本次开台会员。
4. 点击保存到点时间。

成功后云数据库变化：

- `table_sessions` 写入或更新：
  - `tableId`
  - `dueTime`
  - `status = active`
  - `memberOpenid`
- 如果绑定会员且老板设置了开台赠分：
  - `member_points.balance` 增加。
  - `points_ledger(type = table_bonus)` 写流水。

注意：

- 重复保存同一会员同一天同一球桌，不会重复发开台赠分。
- 如果以后接开台软件 API，可以用真实订单 ID 替代当前去重逻辑。

## 7. 球友挑战

负责人：球友双方

入口：

```text
球桌二维码 -> 挑战首页
```

第一版真实路径：

1. 球友扫码进入挑战首页。
2. 小程序检查微信身份。
3. 小程序请求店内定位。
4. 云函数读取老板端门店经纬度，判断是否在 100 米内。
5. 云函数读取 `table_sessions`，判断该球桌是否已开台。
6. 发起挑战。
7. 对手加入。
8. 选择玩法。
9. 选择底分和倍率。
10. 双方确认。
11. 进入计分。
12. 达到目标盘数后进入结算。
13. 满最低时间才允许有效结算。
14. 云函数写入积分、段位、流水、结算单。

成功后云数据库变化：

- `matches` 记录房间和比赛状态。
- `match_score_events` 记录加减盘。
- `settlements` 记录结算结果。
- `points_ledger` 记录双方积分变化。
- `member_points` 更新余额。
- `store_members.rankState / rankTitle` 更新段位。

## 8. 大屏榜单

负责人：老板 / 员工

小程序内入口：

```text
我的 -> 电视大屏
```

当前状态：

- 小程序内大屏可通过 `screen.getBoard` 读取榜单。
- 小米电视浏览器访问的 H5 大屏仍需要最终部署方式。

后续需要确认：

- 小米电视直接打开网页榜单。
- 还是使用投屏。
- 还是配一个安卓盒子或 mini PC 打开固定大屏页。

## 9. 上线前必须跑通的验收

按顺序验收：

1. 老板初始化成功。
2. 老板保存配置成功。
3. 老板扫码把一个微信设成员工。
4. 员工进入前台工作台成功。
5. 员工设置 `T01` 到点时间成功。
6. 员工绑定开台会员后，会员积分增加 30 分。
7. 球友在店内扫码能发起挑战。
8. 店外或拒绝定位不能发起有效挑战。
9. 一场抢 5 完整结算成功。
10. 重复点击结算不会重复改积分。
11. 排行榜读取真实积分。
12. 大屏读取真实榜单。
