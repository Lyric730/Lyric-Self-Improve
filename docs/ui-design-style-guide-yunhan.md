# 云瀚台球俱乐部天梯系统 UI 设计风格规范

状态：用于页面风格评审  
适用范围：球友端、员工端、老板端、电视大屏  
核心比例：球友端游戏感 60%，工具感 40%

## 1. 设计目标

这套 UI 不是普通黑色后台，也不是电竞游戏皮肤。它要解决三个问题：

- 球友在球桌旁能快速开局、快速计分、清楚看到奖励和段位反馈。
- 员工在前台忙的时候能低成本操作，不需要理解复杂规则。
- 老板能配置所有参数，但复杂度只留在老板端。

视觉目标：

```text
黑橙竞技 + 台球厅夜场 + 段位荣誉感 + 简单工具感
```

品牌名先使用：`云瀚台球俱乐部`。  
小程序名称暂不锁死，页面中先以门店品牌露出，不强行设计临时 Logo。

## 2. 视觉母题

UI 的设计细节应该来自台球厅现场，而不是泛泛的“暗黑科技风”。

可以使用：

- 球桌边框的斜切线条。
- 台呢的细微颗粒质感。
- 球袋的半圆 / 弧线暗纹。
- 计分灯牌的数字感。
- 段位徽章、奖章、星级、排名牌。
- 大屏榜单的赛场播报感。

不要使用：

- 无意义发光球、渐变球、背景光斑。
- 紫蓝赛博渐变。
- 毛玻璃卡片堆叠。
- 大面积霓虹描边。
- 渐变文字。
- 一堆等宽等高的黑色圆角卡片。

## 3. 品牌与标识

当前没有 Logo 和门店主题色，所以第一版采用文字标识系统。

建议：

- 主品牌：`云瀚台球俱乐部`
- 英文辅助：`YUNHAN BILLIARDS`
- 小程序名称待定，先不写死在组件和数据结构里。
- 电视大屏左上角使用文字标识，不使用临时球形图标充当 Logo。

文字标识方向：

- 中文为主，英文为辅。
- 字标可以做紧凑横排：`云瀚台球俱乐部 / YUNHAN BILLIARDS`
- 不要用通用 8 号球、皇冠、火焰图标当品牌核心符号。

## 4. 色彩系统

颜色必须有角色，不做装饰性乱用。

| 角色 | 建议方向 | 用途 |
| --- | --- | --- |
| 深色背景 | 微暖炭黑，不用纯黑 | 页面底色、电视背景 |
| 面板底色 | 深灰偏暖，和背景拉开层次 | 计分面板、设置面板、榜单列表 |
| 主橙色 | 高饱和橙，不大面积铺满 | 主按钮、当前选中、关键路径 |
| 奖励金色 | 偏金，不偏黄绿 | 随机奖励、段位、排名、加星 |
| 确认金色 | 橙金 / 暖金，不使用绿色 | 可清算、确认成功 |
| 风险红色 | 干净红，不荧光 | 扣分、异常、时间不足 |
| 文本主色 | 暖白 | 标题和关键文字 |
| 文本次色 | 暖灰 | 说明、状态、辅助信息 |

比例建议：

- 深色和面板：约 70%
- 暖灰文字和边界：约 18%
- 橙色 / 金色强调：约 9%
- 绿 / 红状态色：约 3%

约束：

- 橙色只用于“下一步、开局、奖励、排名、段位”这类高价值动作。
- 金色只用于“奖励 / 段位 / 名次”，不要把普通按钮也做成金色。
- 红色只用于扣分、异常、风险，不用于普通提示。
- 背景不要做大面积渐变；可以用非常弱的台呢纹理和几何暗纹。

## 5. 字体与数字

微信小程序优先保证中文清晰，不为了炫酷牺牲可读性。

建议：

- 中文：使用平台默认高可读中文字体，保证微信端稳定。
- 数字：使用更硬朗、略窄的数字风格，强化计分牌和榜单感。
- 排名、比分、积分变化、时间差，要比说明文字大至少 2 个层级。

约束：

- 不使用花哨艺术字体。
- 不使用大段全大写英文。
- 不用渐变文字。
- 不让小字号说明承担关键规则。

## 6. 布局原则

### 6.1 球友端

球友端是手机上的现场工具，每屏只做一个主任务。

布局原则：

- 顶部：品牌 / 球桌 / 当前状态。
- 中部：当前任务主体，例如玩法、底分、计分、结算。
- 底部：主操作按钮或底部 Tab。
- 关键数字必须在拇指操作区上方可见。
- 按钮高度足够大，避免边打球边误触。

不做：

- 营销式首页。
- 大段规则说明。
- 多层卡片嵌套。
- 每页都放一排无意义数据卡。

### 6.2 员工端

员工端应更像前台工作台，不要强游戏化。

布局原则：

- 入口最多四个：首页房间、开台到点、扣积分、异常比赛。
- 表单字段少，标签直白。
- 默认值明确。
- 危险操作，如作废比赛，必须二次确认。

不做：

- 员工端配置复杂奖励规则。
- 让员工判断比赛是否够最低时间。
- 让员工手算积分。

### 6.3 老板端

老板端可以更密，但必须分组清楚。

分组建议：

- 玩法参数。
- 积分参数。
- 随机奖励。
- 段位规则。
- 排行榜和大屏。
- 防刷分。

设计要求：

- 配置项使用分组面板，组内表单对齐。
- 高风险配置使用二次确认。
- 每个参数必须有默认值。
- 不把所有配置堆成一张长表。

### 6.4 电视大屏

电视大屏是荣誉展示，不是操作页面。

布局原则：

- 16:9 横屏。
- 左上角展示 `云瀚台球俱乐部`。
- 预留门店活动 / Logo / 赞助信息区域，但第一版可为空。
- 前三名必须形成舞台感。
- 4-30 名列表要远距离可读。
- 不展示复杂规则。

## 7. 关键组件规范

### 7.1 玩法卡

玩法卡不是普通卡片，要像“比赛模式牌”。

必须展示：

- 抢几。
- 最低有效时间。
- 默认底分档。
- 加星收益。
- 是否预留。

视觉约束：

- 当前选中状态明显。
- 抢 7 比抢 5 更有奖励感，但不能让抢 5 看起来低级。
- 预留模式要灰掉，但仍能让老板理解未来可开。

### 7.2 底分和倍率选择

使用档位按钮。

必须展示：

```text
风险积分 = 挑战底分 × 积分倍率
```

约束：

- 不允许自由输入底分。
- 不显示“赌注”“赔率”。
- 选项变化时，风险积分要即时更新。

### 7.3 随机奖励模块

随机奖励是本系统的情绪价值重点，不能埋在说明文字里。

必须展示：

- 普通随机奖励范围。
- 续时冲刺奖励范围。
- 第 4 大局 / 续时后冲刺局说明。

视觉建议：

- 使用金色奖励模块。
- 用“系统奖励”作为主标题。
- 结算时奖励数字单独出现，不和风险积分混在一起。

### 7.4 比赛计分面板

比赛页必须像一个真正的计分器。

必须展示：

- 双方头像 / 昵称。
- 双方盘数。
- 双方 `+` / `-`。
- 已进行时间。
- 最低有效时间。
- 还差多久可清算。
- 当前风险积分和系统奖励。

约束：

- `+` 是主动作，面积最大。
- `-` 是纠错动作，弱于 `+`。
- 达到胜利盘数后冻结继续加盘，进入结算判断。
- 不让用户手算积分。

### 7.5 结算面板

结算是仪式感最高的页面。

必须分开展示：

- 胜负结果。
- 风险积分变化。
- 系统随机奖励。
- 最终积分变化。
- 加星 / 掉星。
- 服 / 不服。

视觉建议：

- 胜方使用金色 / 橙金组合，不使用绿色成功态。
- 败方扣分使用红色，但系统奖励仍用金色，避免全屏挫败。
- 加星动画可以比积分动画更有仪式感。

### 7.6 排行榜

排行榜要像店内荣誉墙，不像普通表格。

个人端：

- 店内总榜。
- 同段位榜。
- 好友榜。

电视端：

- 店内总榜。
- 赏金猎人榜。
- 预留活动 / Logo / 赞助信息区。

约束：

- 前三名和普通排名必须有明显层级。
- 不拆分抢 5 / 抢 7 / 抢 10 段位榜。
- 远距离阅读优先，少放小字。

## 8. 动效规范

动效只用在状态变化，不做装饰。

建议：

- 页面切换：轻微上移 + 淡入，150-220ms。
- 选中档位：边框 / 背景 / 数字变化即时响应。
- 可清算：按钮状态从暗到亮，带轻微脉冲一次。
- 系统奖励：数字从下方上浮，金色停留 600-900ms。
- 加星：逐颗点亮，抢 7 连续点亮 2 颗。
- 晋级：段位牌切换，不做长动画。

不做：

- 无限闪烁。
- 大量粒子。
- 弹跳动画。
- 挡住操作的长动画。

## 9. 反 AI 味检查清单

设计和实现前必须逐条检查：

- 页面是否只是黑色背景 + 发光卡片堆叠？如果是，重做。
- 是否用了紫蓝渐变、渐变文字、装饰光球？如果是，删除。
- 每个面板是否长得一样？如果是，重新建立层级。
- 是否把所有信息都塞进圆角卡片？如果是，改成面板、榜单、计分器、奖励条等不同结构。
- 是否有无意义大数字？如果数字不能帮助开局、计分、结算、排名，就删掉。
- 结算页是否能一眼看懂“我赢/输了多少、系统奖多少、段位变了什么”？不能就重排。
- 员工端是否出现需要学习规则才能操作的入口？有就简化。
- 老板端是否把复杂配置给员工或球友看到了？有就移走。
- 电视大屏 3 米外是否能看清前三名和榜单？不能就放大。

## 10. 本轮风格拍板

已确认：

- 继续黑橙竞技方向。
- 品牌使用 `云瀚台球俱乐部`。
- 暂无 Logo，暂无门店主题色。
- 球友端接受游戏感 60%、工具感 40%。
- 电视大屏预留门店活动 / Logo / 赞助信息接口。

仍需后续确认：

- 小程序正式名称。
- 是否需要为 `云瀚台球俱乐部` 设计简易字标。
- 电视大屏预留区默认展示什么：活动、公告、会员权益、赞助信息，还是空位。
