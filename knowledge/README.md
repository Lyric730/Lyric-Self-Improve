# Knowledge

这里放已经从项目、对话、研究里提炼出来的可复用知识。

## 入口

- [_indexes/home.md](_indexes/home.md) - 知识库总入口
- [_indexes/project-map.md](_indexes/project-map.md) - 项目地图
- [_indexes/open-loops.md](_indexes/open-loops.md) - 待整理问题

## 分区

| 目录 | 放什么 | 不放什么 |
| --- | --- | --- |
| `00-inbox/` | 临时收集、还没消化的材料 | 已经形成 SOP 的内容 |
| `ai-workflows/` | 和 AI/Codex 协作的方法、提示词、工作流 | 单个项目的一次性聊天记录 |
| `career/` | 求职、岗位、能力模型的可复用知识 | 某次投递的临时草稿 |
| `content-playbooks/` | 内容生产、自媒体、内容 pipeline SOP | 每日发布包和运行日志 |
| `growth-playbooks/` | 增长、SEO、内容生产的打法 | 项目运行日志 |
| `insights/` | 值得复盘的判断、原则、观察 | 没验证过的碎片观点 |
| `product-playbooks/` | 产品方案、MVP、运营机制、风控 SOP | 项目全部 PRD 原文 |

## 整理规则

1. 先判断材料属于 `knowledge/` 还是 `projects/`。
2. 能跨项目复用，放 `knowledge/`。
3. 只服务于某个项目交付，放 `projects/<project>/`。
4. 来源不明的外部事实要保留链接或标注“来源待查”。
5. 阶段产出成熟后，更新 `_indexes/`，不要只新增孤立文件。
6. 项目里已有 SOP/Workflow/Runbook，复制到 `knowledge/` 对应目录；没有 SOP 的项目先整理首版 SOP。
