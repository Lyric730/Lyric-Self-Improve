来源项目：[projects/Token-Relay/02-成本与问题清单-待解决.md](../../../projects/Token-Relay/02-成本与问题清单-待解决.md)

## 先说风险

这个项目不能先写技术。它的核心风险是资金、合规、上游、合伙、客服和个人职业隔离。技术接通之前，P0 风险没有解决就不应该开站。

## 阶段 0：是否继续

| 必答问题 | 通过标准 |
| --- | --- |
| 公司主体和法人是谁 | 有明确责任主体 |
| 收款主体和运营主体怎么隔离 | 不混用个人品牌和个人实名 |
| 上游是否能签书面协议 | 有断供、退款、保密、价格调整条款 |
| 合伙协议是否写清楚 | 出资、利润、退出、责任、决策机制明确 |
| 预付款是否隔离 | 用户余额不和运营花费混用 |

任何一项答不清，继续做技术都是假进展。

## 阶段 1：开站前 P0

1. 公司主体、法人、收款主体拍板。
2. 合伙协议完成。
3. 上游合作协议完成。
4. 备用上游和断供 24h 应急方案完成。
5. 用户预付款资金隔离方案完成。
6. 个人品牌隔离完成：域名、邮箱、账号、宣传渠道都不关联小刀老师公开身份。

## 阶段 2：最小运营闭环

| 模块 | 最小要求 |
| --- | --- |
| 服务器/域名/SSL | 能稳定访问，有基础监控 |
| Token 供给 | 至少 1 个主上游 + 1 个备上游 |
| 支付 | 手续费、退款、chargeback 规则清楚 |
| 客服 | 工单入口、SLA、排班 |
| 用户文档 | 充值、使用、退款、异常处理 |
| 告警 | 上游异常、余额不足、调用失败 |

## 禁区

- 不用小刀老师的自媒体账号宣传。
- 不用个人实名直接收款。
- 不存用户 prompt，除非合规和隐私政策明确。
- 不让用户预付款进入日常运营开支池。
