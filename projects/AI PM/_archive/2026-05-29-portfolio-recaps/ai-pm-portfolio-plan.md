## 作品集 1：Growth Engine Pipeline

### 定位

AI 内容增长工作流 / Agent-like Pipeline。

它不是普通内容项目。它证明的是：能把开放式信息流任务拆成输入、过滤、聚类、路由、生成、质检、审核、分发、复盘。

### 必须补的证据

| 证据 | 内容 | 完成标准 |
|---|---|---|
| 架构图 | L0 信号采集 -> L1 主题引擎 -> 人工审核 -> L2 写作 -> L3 配图 -> L4 发布 | 一张图能让面试官 30 秒看懂系统 |
| 模块说明 | 每层做什么、输入是什么、输出是什么 | 不讲代码细节，讲产品模块和决策点 |
| 运行样本 | 选 1 次完整 pipeline，从 source item 到文章/发布队列 | 有输入、过程、输出截图或文件路径 |
| 质量门禁 | 12 类问题检测、修复循环、最多 5 轮 | 说明为什么不是“让模型随便写” |
| 人工审核节点 | 选题审核、发布确认、图片授权、最终正文确认 | 说明 human-in-loop 和风险控制 |
| 个人贡献边界 | 哪些是你设计，哪些是你配置，哪些是 AI/Codex 协作实现 | 防止面试被追问代码归属时答乱 |

### 推荐作品集结构

1. 背景：AI 信息太多，选题和内容生产难以持续稳定。
2. 目标：把 AI 信号转成可发布文章，同时保留人工审核和质量控制。
3. 用户/使用者：自己或内容增长操作者。
4. 任务流：采集、聚类、路由、审核、生成、质检、配图、发布。
5. 关键设计：
   - 130+ AI 来源信号。
   - 主题聚类和泛词过滤。
   - 8 条内容泳道。
   - 热度/优先级排序。
   - LLM 写作和质量门禁。
   - 发布队列。
6. 结果：产出文章、减少人工整理成本、形成可复用 SOP。
7. 反思：还缺成本报告、质量报告、失败样本沉淀、runtime 轻量索引。

### 暂不做

- 不把它包装成已经商业化的大产品。
- 不夸大成完全自动发布系统。
- 不写“我独立完成全部工程实现”，除非能逐项证明。

## 作品集 2：产品增长体系复盘

### 定位

产品增长与内容系统能力。

它服务 AI PM 的原因：AI PM 不是只会写 prompt，也要知道产品目标、用户来源、数据指标、内容分发和转化闭环。

### 组成

| 项目 | 证明什么 |
|---|---|
| Yolox SEO | 搜索增长、关键词、内容、外链、GSC/Bing/GA4/Looker、KPI 定义 |
| Self-Media / 三分钟未来 | 选题审核、图文生产、视频/TTS、每日产线、可复用 SOP |
| 高顿 | 早期真实商业增长结果，作为补充证据 |

### 必须补的证据

| 证据 | 内容 | 完成标准 |
|---|---|---|
| 增长链路图 | 信号/需求 -> 内容/页面 -> 分发 -> 指标 -> 复盘 | 不只是列动作，要有闭环 |
| SEO 完整案例 | keyword -> brief -> content -> index/rank/backlink -> KPI | 至少选 1 条能公开或脱敏的案例 |
| 指标表 | impression、click、CTR、session、registration、backlink live/dofollow 等 | 指标定义清楚，不混淆 vanity metric |
| 内容产线案例 | Self-Media 一次从选题到渲染/发布包的流程 | 证明多步骤工作流设计 |
| 复盘页 | 做对了什么、失败什么、下一步怎么优化 | 证明你不是只执行，而是能改系统 |

### 推荐作品集结构

1. 背景：产品需要低成本获得流量和持续内容产出。
2. 增长目标：搜索曝光、内容触达、外链质量、注册/转化。
3. 系统拆解：
   - 数据看板。
   - 关键词研究。
   - Blog/AEO 内容。
   - 外链建设。
   - 内容产线。
4. 指标定义：哪些指标算成功，哪些只是过程信号。
5. 案例：选一条完整链路做证据。
6. 复盘：哪些动作有效，哪些不稳定，下一步怎么系统化。

## 作品集 3：AI 求职 Agent MVP

### 定位

面向 AI PM 求职场景的个人任务 Agent。

它的价值不是“做一个简历生成器”，而是把求职任务拆成：JD 收集、要求聚类、个人经历匹配、能力缺口、学习路线、投递优先级。

### MVP 范围

| 模块 | 输入 | 输出 |
|---|---|---|
| JD 解析 | JD 文本或 URL | 职责、要求、加分项、硬门槛 |
| 要求聚类 | 多个 JD 的要求 | 高频能力表 |
| 个人经历匹配 | 经历素材库 | 可用证据、缺口、风险 |
| 学习路线 | 目标岗位 + 缺口 | 4-8 周学习和项目路线 |
| 投递建议 | 岗位 + 个人画像 | S/A/B/放弃和原因 |

### 必须补的证据

| 证据 | 内容 | 完成标准 |
|---|---|---|
| PRD | 用户、场景、任务、功能、非目标 | 能作为产品文档展示 |
| 数据结构 | JD、能力、项目、证据、缺口 | 不需要复杂，但字段要清楚 |
| 评测样例 | 3-5 个 JD 输入，检查输出是否靠谱 | 能说明判断标准 |
| Demo | 本地脚本、网页、表格工作流均可 | 能跑通一个完整任务 |

### 暂不做

- 不做登录、账号系统、复杂 UI。
- 不做自动投递。
- 不追求大而全，只做能证明 Agent PM 能力的任务闭环。
