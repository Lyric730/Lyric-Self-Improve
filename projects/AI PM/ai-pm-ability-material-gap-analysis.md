# AI PM 能力素材与补强分析

更新日期：2026-05-29  
阶段：经历画像 v2  
用途：把所有项目当作原始能力素材，判断长处、短板、要补的项目和要学习的能力。  

## 判断口径

1. 近期成体系项目优先级高于旧简历项目。
2. 产品增长相关项目优先级拉高，因为它们有流程、指标、SOP、复盘和持续执行。
3. 高顿、NeuralOPT 等旧经历优先级下调，只作为早期能力素材，不作为当前主卖点。
4. NeuralOPT 的 AI 部分不再主打；它只证明早期产品基本功。
5. 所有项目都不直接等于简历经历，先进入“能力素材库”，再决定是否写进简历、作品集或面试故事。

## 项目素材优先级

| 优先级 | 项目 | 当前判断 | 主要用途 |
|---|---|---|---|
| S | Growth Engine Pipeline | 现有项目里最接近 Agent / AI 工具 / 生产力产品 | 主线作品集，证明 AI 工作流、路由、质量门禁、human-in-loop |
| S | Yolox SEO / 产品增长体系 | 近期成体系增长项目 | 证明增长链路、数据指标、搜索、内容、外链和长期执行 |
| A | Self-Media / 三分钟未来 / Digest | 近期内容产线项目 | 证明 AI 内容工作流、选题审核、素材筛选、图文/视频自动化 |
| A | AI PM 求职研究项目 | 当前方向选择与 JD 数据资产 | 可转成 AI 求职 Agent 的需求调研和数据底座 |
| B | Huoshanbei 校园 AI 助手 | 对齐 C 端 AI 助手，但证据未补齐 | 后续补 RAG demo、原型、测试集后可升级 |
| B | 高顿教育产品经理实习 | 真实商业增长经历，但属于旧简历主素材 | 证明早期增长、用户运营、转化、流程产品化 |
| C | NeuralOPT | AI 部分已弱化/废弃，且是早期能力阶段 | 只证明早期调研、竞品、PRD、原型、用户测试 |
| C | Taiqiu XCX | 产品基本功强，但与 AI PM 主线距离较远 | 面试时作为复杂规则简化案例备用 |

## 当前长处

| 长处 | 证据来源 | 怎么讲 |
|---|---|---|
| 系统化产品增长 | Yolox SEO、Self-Media、Growth Engine、高顿 | 不是只做单点运营，而是能搭流程、看指标、沉淀 SOP |
| AI 工作流设计 | Growth Engine、Self-Media、AI PM 求职研究 | 能把开放任务拆成输入、处理、审核、输出、复盘 |
| 信息组织和研究能力 | AI PM JD 研究、Yolox 关键词研究、Growth Engine 信号处理 | 能把大量信息整理成结构化决策材料 |
| 产品基本功 | 高顿、NeuralOPT、Taiqiu XCX、Huoshanbei | 有调研、竞品、原型、PRD、测试、流程设计素材 |
| solo-op 执行密度 | 多项目 SOP、README、自动化产线 | 能自己推进从需求、工具、产出到复盘的完整链路 |

## 当前短板

| 短板 | 具体问题 | 优先级 |
|---|---|---|
| AI 技术表达不够硬 | LLM、Agent、RAG、Prompt、评测、工具调用还需要准确表达 | S |
| 可演示物不足 | Growth Engine 缺公开复盘包；AI 求职 Agent 未做 MVP；Huoshanbei 缺 demo | S |
| 评测体系不够标准 | 现在有质量门禁和测试题，但还不是系统化 evals | S |
| 编程边界不清 | 需要说明哪些是自己写、哪些是 AI/Codex 协作、自己能 debug 到什么程度 | A |
| 用户验证不足 | 近期项目偏自用/产线，缺真实用户访谈、可用性测试、留存/满意度数据 | A |
| 旧经历容易压低当前能力感 | 高顿、NeuralOPT 如果放太前，会让招聘方看到的是一年前能力水平 | A |

## 要补的项目证据

| 项目 | 现在缺什么 | 补完后的价值 |
|---|---|---|
| Growth Engine Pipeline | 架构图、模块说明、一次完整运行样本、质量门禁日志、发布结果、个人贡献边界 | 直接变成 S 级 Agent / AI 工作流作品集 |
| Yolox SEO / 产品增长体系 | 一条从 keyword -> brief -> content -> index/rank/backlink -> KPI 的完整案例 | 证明增长闭环，不只是做了很多 SEO 动作 |
| Self-Media / 三分钟未来 | 产线流程图、输入输出样例、人工审核节点、失败样本和修复规则 | 证明 AI 内容产线设计，而不是自媒体运营 |
| AI 求职 Agent | MVP 功能定义、数据结构、简历匹配规则、学习路线生成、评测样例 | 变成面向求职场景的垂直 Agent 主作品 |
| Huoshanbei 校园 AI 助手 | RAG 数据源、意图路由、敏感问题处理、50 题测试集、原型/demo | 作为 C 端 AI 助手副线作品 |
| 高顿 | 压缩成增长闭环 bullet，不再补大文档 | 作为商业结果背书 |
| NeuralOPT | 不补 AI 机制，只整理 PRD/原型/用户测试过程 | 作为早期产品基本功背书 |

## 要学习的能力

| 学习项 | 学到什么程度 | 对应项目 |
|---|---|---|
| LLM / Agent 基础 | 能讲清任务拆解、工具调用、上下文、记忆、失败兜底 | Growth Engine、AI 求职 Agent |
| RAG | 能讲清数据源、切分、召回、重排、引用、幻觉控制 | Huoshanbei、AI 求职 Agent |
| Prompt 工程 | 能把 prompt 设计成可复用链路，而不是临时指令 | Growth Engine、Self-Media |
| Evals / 质量评测 | 能定义测试集、通过率、失败类型、修复策略 | Growth Engine、Huoshanbei、AI 求职 Agent |
| 产品数据分析 | 能把 CTR、转化、SEO、内容产出、质量通过率变成指标体系 | Yolox、高顿、Growth Engine |
| 基础 coding / AI coding | 能读脚本、改配置、跑 pipeline、定位常见错误 | Growth Engine、Self-Media、AI 求职 Agent |
| C 端 AI 助手体验 | 能分析首轮体验、追问、引用、纠错、留存和反馈入口 | Huoshanbei、AI 求职 Agent |
