## 核心判断

现在不能继续泛泛地说“我要做 AI 产品经理”。  
正确问题是：

> 我要做哪一类用户、哪一层 AI 能力、哪一种业务场景里的 AI 产品经理？

AI PM 不是单一岗位，而是岗位族。不同方向要求差异很大：

- Agent 产品经理：看任务流、工具调用、上下文、评测、失败兜底。
- AIGC 产品经理：看创作流程、生成质量、内容审美、用户创作需求。
- AI 平台产品经理：看 API、模型服务、开发者工具、MaaS、企业场景。
- 垂直业务 AI PM：看电商、客服、医疗、办公、搜索等具体业务。
- 模型评测 / 数据产品经理：看数据集、Benchmark、标注、训练反馈。
- AI 运营 / 增长产品：看用户增长、留存、商业化、内容和社区运营。

如果方向不定，学习路线会发散，作品集也会没有清晰命中点。

## 选择标准

本阶段先用 6 个标准筛方向。

| 标准 | 解释 |
|---|---|
| JD 覆盖面 | 岗位数量是否足够多，是否能覆盖北京/深圳主流公司 |
| 区分度 | 能不能和普通产品经理拉开差距 |
| 新手可进入性 | 能不能从 0 做出可证明能力的作品 |
| 作品集可操作性 | 4-8 周内能不能做出能展示的项目 |
| 和个人长期方向匹配 | 是否适合 solo-op、知识管理、AI 工具、增长、学习型路线 |
| 风险 | 是否过度依赖强行业背景、强算法背景、强大厂履历 |

## 初步推荐

### 主线：Agent / AI 工具 / 知识工作流产品

这是目前最值得优先押注的方向。

理由：
- 它和 JD 高频能力重合：AI 基础理解、数据分析、沟通推进、用户研究、产品设计。
- 它和区分度能力重合：Agent/Prompt/RAG、编程/工程理解、模型评测/数据闭环。
- 它适合做个人作品集：可以做一个可运行的 AI 工作流、知识库、任务型 Agent、评测面板。
- 它和个人长期方向匹配：知识管理、学习提升、solo-op 工具、AI 辅助工作流，都能放进同一条叙事。

这个方向不是“做聊天机器人”。  
更具体地说，是：

> 设计一个 AI 系统，让用户完成一个明确任务，并能评估它完成得好不好。

具体例子：
- AI 求职助手：抓 JD、聚类能力、匹配简历、生成学习计划、追踪投递。
- AI 知识管理助手：收集资料、整理笔记、生成主题地图、做问答和复习。
- AI 研究工作流 Agent：搜索、摘取证据、生成报告、标注来源、输出结论。
- AI coding / no-code 工具助手：把需求拆成任务、生成代码、运行验证、总结错误。

### 副线：AIGC / 创作工具 或 C 端 AI 应用

副线建议二选一。

#### 选 AIGC / 创作工具的条件

适合你如果：
- 你愿意长期做内容、视频、图文、创作者工具。
- 你能做出可视化作品集。
- 你愿意研究可灵、即梦、剪映、Vidu、Runway、Midjourney、CapCut 等产品。

风险：
- 需要审美和内容判断。
- 很多岗位会要求多模态、创作流程、海外产品认知。

#### 选 C 端 AI 应用的条件

适合你如果：
- 你更想做 Kimi、豆包、元宝、小爱、飞书 AI 这类大众或办公产品。
- 你愿意做用户研究、交互、留存、反馈闭环。
- 你希望降低一点技术门槛，但仍保留 AI PM 方向。

风险：
- 竞争会更接近传统 C 端 PM。
- 如果作品集只是“做一个 AI 聊天页面”，区分度不够。

## 暂不建议作为第一主线

| 方向 | 原因 |
|---|---|
| 纯 AI 平台 / MaaS / API | 长期好，但对技术、B 端、开发者场景要求更高；可以作为第二阶段升级 |
| 垂直医疗 / 金融 / 供应链 AI | 没有行业经验时说服力弱；除非你愿意专门补一个行业 |
| AI 解决方案 / 售前产品 | 容易偏交付/客户方案，不一定沉淀标准产品能力 |
| 纯模型评测 / 数据产品 | 能力很关键，但直接作为求职主线偏硬；更适合作为 Agent 主线里的核心模块 |

## 方向选择建议

当前建议采用：

| 层级 | 选择 |
|---|---|
| 主线 | Agent / AI 工具 / 知识工作流产品 |
| 副线 A | C 端 AI 应用 |
| 副线 B | AIGC / 创作工具 |
| 能力底座 | 数据分析、用户研究、产品设计、Prompt/RAG/Agent、评测体系、基础 coding |
| 暂缓 | 纯 ToB 平台、行业解决方案、医疗/金融深行业、纯模型数据岗 |

## 接下来需要确认的 5 个问题

这 5 个问题回答完，才能从“初步推荐”进入“正式求职定位”。

1. 你更想做 C 端产品，还是 B 端 / 开发者工具？
2. 你更愿意面对普通用户、创作者、开发者，还是企业客户？
3. 你能接受补 coding 到什么程度：只会用 AI 写脚本，还是愿意系统学 Python/API/SQL？
4. 你希望作品集偏“可运行工具”，还是偏“产品分析 + 原型 + 方案”？
5. 你更想投北京/深圳大厂，还是也接受 AI 原生创业公司？

## 当前阶段结论

先不要继续无限扩 JD。  
下一步应该做方向收敛：

> 主线先定为 Agent / AI 工具 / 知识工作流产品；再在 C 端 AI 应用和 AIGC 创作工具里选一个副线。

这个组合既能覆盖较多岗位，也能做出个人作品集，还能把知识管理、AI 工具使用、求职提升这些已有主题串成一条清晰叙事。
