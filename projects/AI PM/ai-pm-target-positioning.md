## 一句话定位

面向个人用户和知识工作场景，做能完成明确任务的 AI Agent / AI 助手产品经理。

更具体一点：

> 不是做泛泛的聊天机器人，而是设计 AI 系统，让用户完成搜索、整理、写作、学习、求职、编程、知识管理等明确任务，并能评估任务完成质量。

## 暂不作为第一阶段主投

| 方向 | 原因 |
|---|---|
| 纯 AIGC / 创作工具 | 感兴趣优先级低于 Agent 和 C 端 AI 助手，先不分散 |
| 纯 ToB AI 平台 / MaaS / API | 可作为技术增强线，但第一阶段主线不放这里 |
| 医疗 / 金融 / 供应链等深行业 AI | 行业门槛高，没有行业经验时不适合做第一主线 |
| AI 解决方案 / 售前产品 | 容易偏交付和客户方案，不一定沉淀标准产品能力 |
| 纯模型数据 / 评测岗 | 能力要补，但不作为第一阶段求职岗位名主线 |

## 能力叙事

这条路线的简历和作品集要讲清楚 5 件事：

1. 我理解 AI Agent / AI 助手能做什么、不能做什么。
2. 我能把用户任务拆成产品流程。
3. 我能设计 Prompt、RAG、工具调用、上下文和失败兜底。
4. 我能用指标和评测判断产品效果。
5. 我能用基础 coding / AI coding 做低成本 demo。

## 当前求职 Skill 工作流

当前主线不再是先做项目复盘，而是把求职规划做成可复用 Skill：

| 步骤 | 目标 | 输出 |
|---|---|---|
| 1 | 方向判断：测试题或用户直接输入方向 | `career-direction-diagnosis.md` |
| 2 | 根据方向获取大厂岗位范围和 JD，聚类岗位要求 | `jd-corpus.md`、`jd-requirement-frequency.md` |
| 3 | 从简历和项目目录中抽取用户原子能力 | `user-atomic-ability-map.md` |
| 4A | 做能力补强规划：学习内容、课程资源、补强项目 | `ability-gap-learning-roadmap.md` |
| 4B | 做求职材料改造：简历、项目、作品集调整 | `resume-project-rewrite-plan.md` |
| 5 | 整合最终行动计划 | `career-action-plan.md` |

当前最推荐：

> 先做 `career-direction-diagnostic-test.md`，把 Step 1 固化下来。

原因：
- 方向判断是后续 JD 搜索、能力抽取、补强规划和简历改造的入口。
- 如果用户已经明确方向，可以跳过测试题，直接进入 JD 研究。
- 复盘材料已归档，后续只作为原始能力素材，不再当当前主线。
