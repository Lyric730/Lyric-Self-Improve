# AI PM 简历与项目改造方案

更新日期：2026-05-29  
阶段：Step 4B v1  
适用方向：Agent / AI 工具 / 生产力产品；副线为 C 端 AI 助手 / AI 应用  
配套文件：[ability-gap-learning-roadmap.md](ability-gap-learning-roadmap.md)  

## 结论

第一版 AI PM 简历不要按时间线写，也不要把旧简历里的高顿、NeuralOPT 放到最前面。应按“当前能力最强、最贴近目标岗位”的逻辑重排：

1. Growth Engine Pipeline：AI 工作流 / Agent-like Pipeline。
2. Yolox SEO + Self-Media：产品增长体系 / 内容与搜索增长。
3. AI PM 求职研究 / AI 求职 Agent MVP：方向研究 + 新补强项目。
4. 高顿教育产品经理实习：真实商业增长和早期产品化证据。
5. NeuralOPT：早期产品基本功，压缩处理，不再主打 AI。

## 简历主叙事

### 推荐定位

> 产品增长和 AI 工作流背景的 AI 工具型 PM 候选人，擅长把真实任务拆成流程、指标、质量门禁和可复用 SOP，并用 AI 工具构建低成本可验证 demo。

### 更聚焦版本

> 面向个人效率和知识工作场景的 AI 产品经理方向，具备 Agent-like 工作流、内容增长系统、SEO 数据指标和 AI 求职研究项目经验。

### 不建议版本

| 说法 | 问题 |
|---|---|
| 资深 AI 产品经理 | 年限和商业化 AI 产品证据不够 |
| 大模型算法背景 | 没有训练/算法研究经历 |
| AI+教育产品专家 | NeuralOPT AI 部分已弱化，会把叙事拉回旧项目 |
| 自媒体运营 / SEO 运营 | 会低估产品增长和系统设计能力 |

## 项目改造方案

### 1. Growth Engine Pipeline

改造目标：从“内容生产项目”改成“AI 工作流产品项目”。

#### 应补证据

| 证据 | 用途 |
|---|---|
| 系统架构图 | 证明任务拆解和模块设计 |
| 一次运行样本 | 证明不是停留在想法 |
| 质量门禁规则 | 证明 evals / 质量意识 |
| 人工审核节点 | 证明 human-in-loop |
| 个人贡献边界 | 防止面试追问工程实现归属 |

#### 简历 bullet 草案

```text
设计 AI 内容增长 Pipeline，将多来源 AI 信号标准化为 source item，并拆解为信号采集、主题聚类、泳道路由、人工审核、LLM 写作、质量门禁、配图和发布队列等模块。
```

```text
制定主题优先级和 8 条内容泳道路由规则，将 AI 信号按发布解读、信号解码、结果证明、对比筛选等策略分发，提升选题判断和内容产出稳定性。
```

```text
设计 LLM 写作质量门禁和修复循环，对文章草稿进行规则检测、失败归因和多轮修复，避免低质 AI 句式、证据不足和格式问题直接进入发布环节。
```

```text
沉淀 SOP 与运行产物索引，形成从信号采集到发布队列的可复用 AI 工作流，为后续 Agent / AI 工具产品能力补强提供案例。
```

#### 风险

| 风险 | 处理 |
|---|---|
| 被问“你写了多少代码” | 准备个人贡献边界：需求/架构/规则/配置/代码协作 |
| 被问“最终发布效果” | 区分生成结果、发布结果、反馈数据，不混说 |
| 被问“质量门禁怎么评估” | 补 failure taxonomy 和 eval set |

### 2. Yolox SEO + Self-Media 产品增长体系

改造目标：从“SEO / 自媒体”改成“产品增长系统”。

#### 应补证据

| 证据 | 用途 |
|---|---|
| 增长链路图 | 证明不是单点执行 |
| GSC / GA4 / Looker 指标截图或脱敏表 | 证明数据意识 |
| 关键词 -> brief -> content -> index/rank/backlink -> KPI 案例 | 证明完整增长闭环 |
| Self-Media 产线样本 | 证明内容工作流和自动化 |
| 复盘结论 | 证明能优化系统 |

#### 简历 bullet 草案

```text
围绕 Yolox 搭建 SEO 增长执行体系，覆盖 GSC / Bing / GA4 / Looker 数据看板、关键词研究、Blog/AEO 内容、外链 KPI 和技术 SEO 修补。
```

```text
将关键词研究、SERP 分析、社区问题、PAA、Pillar/Cluster 和 L6 大纲沉淀为内容生产 SOP，用于稳定产出可被搜索和 AI 问答引用的内容。
```

```text
定义外链建设硬 KPI 为 status='live' AND rel_actual='dofollow'，区分提交、待审核、已收录和真实 SEO 价值，避免用虚假过程指标判断增长效果。
```

```text
搭建 Self-Media 内容产线，将选题审核、素材筛选、图文渲染、TTS/视频生成和发布包沉淀为可复用流程，提升内容生产稳定性。
```

#### 风险

| 风险 | 处理 |
|---|---|
| 被理解成 SEO 运营 | 强调“指标体系 + 内容结构 + 自动化流程 + 复盘” |
| 数据不能公开 | 做脱敏版指标表 |
| 内容项目太散 | 只选一个完整案例，不堆所有内容 |

### 3. AI PM 求职研究 / AI 求职 Agent MVP

改造目标：从“求职研究”升级成“AI 求职 Agent 项目”。

#### 当前已有

| 已有材料 | 用途 |
|---|---|
| 目标公司表 | Agent 的公司/岗位数据源 |
| JD 材料 | Agent 的语料库 |
| JD 要求频率聚类 | 能力标签和权重 |
| 个人能力分析 | 简历匹配输入 |
| Future Career Job Search Skill 草案 | 产品流程和功能边界 |

#### 应补证据

| 证据 | 用途 |
|---|---|
| PRD | 证明产品定义能力 |
| 数据结构 | 证明不是只聊天 |
| MVP demo | 证明能跑通任务 |
| 10 条 eval 样例 | 证明评测意识 |
| 1 个完整输出案例 | 证明对用户有价值 |

#### 简历 bullet 草案

```text
基于 46 条 AI PM JD 样本，建立岗位要求聚类和频率统计，将 AI/大模型、数据指标、用户研究、产品设计、Agent/Prompt/RAG、评测等能力拆成可匹配标签。
```

```text
设计 AI 求职 Agent 工作流，覆盖方向判断、JD 获取、岗位要求聚类、用户原子能力抽取、能力补强规划和简历项目改造，形成可复用求职 Skill 草案。
```

```text
规划 AI 求职 Agent MVP：输入目标方向、JD 和简历/项目目录，输出能力缺口、学习资源、补强项目和简历改造方案，并用测试样例验证输出质量。
```

#### 风险

| 风险 | 处理 |
|---|---|
| 目前还没有 demo | 先写“设计/规划”，demo 做完后再写“实现/搭建” |
| JD 样本不是全市场 | 明确样本范围和来源，不夸大 |
| 容易像咨询报告 | 必须补可运行 MVP 或半自动工作流 |

### 4. 高顿教育产品经理实习

改造目标：压缩为“真实商业增长 + 业务流程产品化”。

#### 保留点

| 保留 | 原因 |
|---|---|
| CTR +24% | 有量化结果 |
| 线索 124、成交 18.2 万 | 有业务结果 |
| 线索管理系统原型 | 产品化证据 |
| 飞书多维表格看板 | 数据/流程工具证据 |

#### 简历 bullet 草案

```text
基于小红书后台和灰豚数据分析平台，定位推文 CTR 低于历史均值的问题，拆解标题、选题、发布时间等变量并重构内容策略，使点击率提升 24%。
```

```text
运营 2 个小红书账号和 5 个社群，结合校园公众号合作、线上活动和公开分享会完成获客链路，累计沉淀 124 条线索并带来 18.2 万元成交额。
```

```text
设计“高顿合伙人”线索管理系统原型和飞书多维表格看板，将线索分发、状态跟踪和数据复盘流程产品化，分别节省人均 30min 和 20min。
```

#### 风险

| 风险 | 处理 |
|---|---|
| 太像运营 | 把重点放在“数据诊断 + 流程工具 + 转化结果” |
| 与 AI PM 距离远 | 放在后面，作为增长和商业结果背书 |

### 5. NeuralOPT

改造目标：不再主打 AI，只保留早期产品基本功。

#### 保留点

| 保留 | 原因 |
|---|---|
| 20 位用户调研 | 用户研究能力 |
| 竞品分析 | 市场/竞品能力 |
| Figma 原型 | 交互和方案表达 |
| PRD | 产品文档能力 |
| 5 位用户测试 | 迭代意识 |

#### 简历 bullet 草案

```text
作为项目组长负责高校商业决策模拟平台的产品设计，完成 20 位目标用户调研、竞品分析、3 类用户画像、Figma 原型和 PRD 文档。
```

```text
邀请 5 位用户测试 MVP，收集 7 条反馈并迭代原型，沉淀页面元素、状态、交互逻辑和异常场景说明。
```

#### 不建议写

- 不写“AI+商业决策平台”作为核心卖点。
- 不展开“AI 即时反馈”，除非你能补清楚机制。
- 不放在 Growth Engine 和产品增长体系前面。
