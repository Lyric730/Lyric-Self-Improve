# docs 目录说明

`docs/` 只放跨产线、可交接、可回看的文档。某条产线的操作手册优先放在 `lines/<line-name>/`，不要把所有细节都堆到这里。

## 子目录

| 目录 | 放什么 | 什么时候看 |
|---|---|---|
| `handoffs/` | 阶段交接文档，记录某次上下文结束时的真实状态 | 接着上次继续做 |
| `proposals/` | 方案、改版建议、待确认设计 | 做大改前 |
| `archive/` | 已完成、废弃或只作历史参考的设计和计划 | 查历史原因 |
| `superpowers/plans/` | Superpowers 生成的执行计划 | 复盘某次工程计划 |

## 根目录文档

| 文件 | 用途 |
|---|---|
| `PROJECT_STRUCTURE.md` | 项目目录结构和放置规则 |

## 写文档规则

- 新事实要写绝对日期，例如 `2026-05-28`，避免使用相对时间词。
- 阶段产物优先写成可复用文档，不只留在聊天窗口。
- 交接文档只记录真实状态，不写愿望清单。
- 方案文档必须说清楚范围、取舍、交付物、验证方式。
