## 一句话先

> **Token 中转站 = AI 时代的奶茶代购店**：
> 你不种茶（不是 OpenAI），你也不喝茶（不是用户），你是中间的"代购"——批发茶水、改包装、按杯卖给客人。

## 整个店铺的 7 个零件

```
        客人
         ↓
[自助点单屏] ← 网页 / App
         ↓
[收银台]    ← 微信 / 支付宝 / USDT 收钱
         ↓
[后厨大脑]  ← 整个生意的核心
   ↑     ↓
[账本] [茶叶批发]  ← 上游账号池在这一层
         
[店面]    ← 服务器
[招牌]    ← 域名
[保安]    ← Cloudflare（防 DDoS）
```

| # | 零件 | 真实身份 | 类比解释 |
|---|---|---|---|
| 1 | 店面 | 服务器（VPS）| 虚拟的"房子"放你所有东西 |
| 2 | 招牌 | 域名（如 xxx.com）| 客人怎么记住你 |
| 3 | 保安 | CDN（Cloudflare）| 挡坏人、加速、防 DDoS |
| 4 | 自助点单屏 | 前端后台 | 客人自己充钱、看用量 |
| 5 | 收银台 | 支付通道 | 收钱的渠道 |
| 6 | **后厨大脑** | **网关程序** | **整个生意的核心，下面单讲** |
| 7 | 茶叶批发 | 上游账号池 | 我们这次要对接的就是这个 |

## 后厨大脑（最关键的一层）

整个生意能不能赚钱，全看后厨。它做 5 件事：

| 步骤 | 真实做的事 | 奶茶店类比 |
|---|---|---|
| **1 验身份** | 检查客人 API key 有没有效、余额够不够 | 收银员看会员卡 + 余额 |
| **2 找供货商** | 决定这一单从哪个上游 key 取 | 看哪个茶叶罐有货 |
| **3 称重计价** | 算这一单用了多少 token、扣多少钱 | 按毫升收钱 |
| **4 限购** | 防止一个人一秒下 100 单打爆系统 | 限购 10 杯/小时 |
| **5 记账** | 每一单都记下来（谁买的、用了多少、谁的茶叶）| 流水账本 |

**好消息**：这套软件**有开源轮子**，叫 `one-api`——**一行 docker 命令就能跑起来**。我们不用从零写。90% 的中转站底层都是它。

## 我们的位置 & 上游的位置

```
[OpenAI 茶园（美国）]        ← 真正种茶的
       ↓ 批发
[上游账号池公司]              ← 这次要对接的"批发商"
       ↓ 二级批发
[我们的店]                    ← 加价 + 改包装 + 客服 + 收钱
       ↓ 零售
[客人]                        ← 在我们这买 API key 的用户
```

### 关键问题：批发商的茶叶哪来的？

OpenAI 不直接卖给批发商——OpenAI 只卖给"真喝茶的人"（按月订阅 ChatGPT Plus $20）。批发商怎么搞到这么多茶水转卖？

**两种方式**：

| 方式 | 说人话 |
|---|---|
| 正大光明 | 开 OpenAI 商业账户，按 API 调用付钱，加价转卖 |
| **反代 token** | 注册一堆 ChatGPT Plus 个人账户（$22 包月无限喝），把每个账户"挤"出来的茶水变成 API 卖 |

**我们对接的这家上游 = 第二种**。

这意味着什么：
- 茶叶来源便宜（白嫖 Plus 的 $22 包月）
- 但 OpenAI 一旦发现这些账号"商业转售"，会一批一批封号
- 1000 个账号 = 万一损失 1000 个 Plus 的钱（$22,000）
- 这就是为啥要"千号池" + 自动养号 = 死了就补

**我们的风险**：上游账号池被大封 → 我们用户的服务断 → 用户骂我们 → 我们要么有备用，要么挂掉。

## 我们要做什么（具体工作分三档）

### 🔴 一定要做（不做就开不了店）

| 任务 | 用时 | 难度 |
|---|---|---|
| 买服务器 + 注册域名 + 套 Cloudflare | 1 天 | 简单 |
| 装 one-api 跑通基础 | 1 小时 | 简单（docker 一行）|
| 配置上游账号池为渠道 | 1 天 | 中（要测稳定性）|
| 接支付通道 | **1-2 周** | 难（最难的一步）|
| 写说明书 + 教程 | 3 天 | 简单 |

### 🟡 应该做（关系到能不能持续）

| 任务 | 用时 |
|---|---|
| 监控告警（上游断了立刻通知）| 2 天 |
| 用户群 / 工单系统 | 3 天 |
| 定期对账 + 报表 | 持续 |
| 备用上游（不能 all-in 一家）| 1 周 |

### ⚪ 必须想清楚（关系到能不能不出事）

- [ ] 谁是法人？公司主体怎么注册？
- [ ] 上游突然停服 24 小时怎么办？
- [ ] 钱怎么分？
- [ ] 什么情况下不做了？

这些**不是技术问题，是商业 / 法律 / 朋友间的约定**——需要和合伙人坐下来谈清楚。

## 一句话结论

> 技术上这是个**已经被开源软件做完 90% 的生意**。
>
> 真正的难点不在技术，在 3 件事：
> 1. **上游靠不靠谱**——茶叶供应商的命脉
> 2. **支付怎么收**——中国大陆收钱通道
> 3. **出事怎么收尾**——合伙人 + 法律 + 朋友关系
