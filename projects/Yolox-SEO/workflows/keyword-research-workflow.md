# 关键词研究流程

目标：把搜索机会转成可写、可排名、可转化的 Blog 选题，而不是只做一张漂亮词表。

## 输入

- 产品能力和 ICP 痛点。
- 竞品和替代方案清单。
- GAKP / KWFinder / Ahrefs / DataForSEO 等工具导出的量化数据。
- Reddit、Quora、HN、Indie Hackers、Google PAA 等真实问题来源。

## 执行

1. 从产品功能、ICP 痛点、竞品比较、新兴生态四类来源做 seed keyword。
2. 扩词优先级：已验证有量的词、真实社区问题、PAA / related searches、规模化工具。
3. 验证每个候选词的 SERP、搜索意图、社区证据、PAA、AI Overview 机会、产品匹配。
4. 用 Volume、KD、Intent、Growth、ICP、Product fit 六个维度打分。
5. 分层为 Tier 1、Tier 1.5、Tier 2、Tier 3、Negative。
6. 先组织 cluster，再组织 pillar；pillar 至少能挂 5 个 cluster。
7. 给 Blog 交付 L6 outline：primary keyword、secondary keywords、LSI、意图、读者、真实问题、SERP 常见答案、产品角度、H1、TL;DR、H2/H3、FAQ、内链、证据链接。

## 完成标准

- 有主关键词表、负向词表、pillar / cluster 图谱。
- 每个进入写作的 topic 都有 brief 级信息，而不是只有标题。
- Tier 1.5 词没有被工具 volume 机械杀掉，保留了真实社区证据强、产品匹配强的机会。

## 常见坑

- 不要凭空生成大批 `Agent x ICP x 场景` 词表。
- GAKP 要看 Historical metrics，不把 Forecast 当判断依据。
- 单个孤立社区帖子不能直接当强证据。
