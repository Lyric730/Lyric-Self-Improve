# Design Context: 云瀚台球俱乐部 Ladder MVP

## Brand

- Store brand: 云瀚台球俱乐部
- Mini program name: TBD; do not lock it yet.
- Logo: none for now. Use a text-first wordmark placeholder, not a generic billiard icon.
- Store theme color: none for now. Product theme uses the app design palette.

## Target Audience

- Billiards players using a WeChat mini program at the table while playing.
- Front-desk staff who need fast, low-learning-cost operations during business hours.
- Store owners who need configurable rules without exposing complexity to players.
- In-store TV viewers who read rankings from several meters away.

## Core Use Cases

- Players scan a table QR code, create or join a challenge, choose mode, base points, and multiplier.
- Players record racks with large `+` / `-` controls during the match.
- Players confirm settlement with clear point, reward, and rank feedback.
- Staff set table due time, handle abnormal matches, and deduct points for offline redemption.
- Owners configure all numeric parameters, rewards, rank rules, anti-cheat, and screen display.
- TV screen shows in-store ranking and bounty-hunter ranking with strong honor value.

## Brand Personality

The interface should feel like a black-orange competitive billiards hall system:

- Energetic, but not noisy.
- Game-like, but still easy to operate.
- Rewarding and ceremonial at settlement moments.
- Dense and practical for staff and owners.
- High-contrast and readable in a nighttime venue.
- It should feel designed, not like a generic dark dashboard.

## Visual Concept

Core direction:

```text
black-orange competitive / billiards night venue / rank ceremony / simple tool
```

Player side ratio: 60% game feeling, 40% tool feeling.

Use the physical language of a billiards hall:

- table-felt depth, rail geometry, pocket arcs, score-light panels, match boards
- not decorative blobs, bokeh, generic neon, or glassmorphism
- surfaces should feel like purposeful equipment panels, not random cards

## Visual System Constraints

- Black and charcoal are the base, but never pure black.
- Orange and gold are scarce accents for primary action, reward, rank, and screen highlights.
- Green is only for success / can settle / confirmed.
- Red is only for danger / deduction / time insufficient / abnormal.
- Avoid purple-blue gradients, cyan neon, oversized glow, gradient text, and generic glass cards.
- Use angled cuts, table-rail lines, engraved labels, compact score modules, and medal/rank motifs deliberately.
- Do not build the page as a pile of same-looking rounded cards.
- No nested cards.
- Cards can exist for repeated items and admin panels, but major page sections should feel like panels/bands.
- Use strong numeric hierarchy: score, risk points, rewards, rank, and time must be visually dominant.
- TV pages prioritize 16:9 composition and long-distance readability.

## Design Principles

- Mechanism simple, operation simple.
- One primary task per player page.
- Random reward and settlement feedback must be visually prominent.
- Staff pages should minimize judgment and manual calculation.
- Owner pages can be denser, but must group settings clearly.
- TV pages prioritize long-distance readability over detailed explanation.
- Every visual flourish must explain game state, rank, reward, or action priority.
- UI details should have constraints: color role, spacing role, motion role, and information role.

## Anti-Goals

- No marketing landing page as the main experience.
- No separate rank per game mode; all ranked modes share one player rank.
- No complicated online point mall in MVP.
- No decorative complexity that makes players or staff think harder.
- No AI-looking dark dashboard: no generic glowing cards, no gradient text, no decorative orbs, no random glassmorphism.
- No stock SaaS admin look on the player side.
- No esports overkill that makes staff or casual players feel confused.
