# 04. 开台、店内验证与反刷分

> 返回：[方案导航](../ladder-simple-operation-plan.md)

> 员工端交互原则：员工只做必要动作，优先保留「设置开台到点时间、查看开台状态、作废异常比赛、前台扣积分」四类操作；复杂参数、玩法配置和奖励规则放到老板端。

## 13. 开台软件对接策略

现在已有开台软件，但不知道是否支持 API。

第一版建议不要强依赖开台软件。

### 13.1 第一版

采用「开台到点提醒」：

- 开台软件继续管计费和开台。
- 小程序只记录比赛和积分。
- 员工在小程序里设置该桌开台到点时间。
- 小程序不要求员工判断当前比赛还够不够时间。
- 到开台时间后，小程序提醒顾客和员工续时。
- 续时后，员工只把开台到点时间往后改。

优点：

- 不等软件厂商。
- 不改原有开台流程。
- 成本最低。
- 出问题容易人工修正。
- 员工不需要计算剩余分钟，也不需要判断比赛时长，只要维护开台到点时间。

缺点：

- 需要员工在开台或续时后维护到点时间。
- 如果员工忘记更新到点时间，续时提醒会不精准。

### 13.2 第二阶段

如果开台软件支持：

- API。
- 数据库读取。
- 订单导出。
- Webhook。

再做自动同步。

### 13.3 不建议第一版做

- 抓屏识别开台软件时间。
- OCR 开台软件界面。
- 直接读取未知数据库。
- 反向破解开台软件。

这些方案不稳定，也容易维护困难。

## 14. 店内验证与反刷分

要避免用户在店外扫码刷分，第一版不要只依赖地理位置。推荐使用多层验证：

### 14.1 开赛前验证

必须同时满足：

1. 员工已经为该球桌设置有效开台到点时间。
2. 两个不同微信用户扫码进入同一张球桌。
3. 两人扫码时间间隔在允许范围内，例如 3 分钟内。
4. 用户开始比赛时通过地理位置校验，距离门店 100 米内。
5. 双方积分余额足够本场风险积分。

任何一项不满足，只能开娱乐局，不能开积分挑战。

### 14.2 结算前验证

结算时再次检查：

- 是否满足玩法最低有效时间。
- 该桌是否有有效开台到点时间或续时记录。
- 是否仍在门店 100 米范围内。

不设置同一组人每日有效挑战上限。只要满足店内验证、开台到点时间、最低有效时间和双方确认，就可以连续挑战。

### 14.3 动态桌码预留

如果后续发现固定二维码被拍照带走刷分，可以升级为动态桌码：

- 员工端为某张桌生成动态码。
- 动态码有效期 3 分钟。
- 两名玩家必须在有效期内扫码。
- 过期后重新生成。

第一版可以先用「员工设置开台到点时间 + 球桌扫码 + 100 米地理位置 + 最低有效时间」，已经能挡住大部分店外刷分。
